# 任务契约

派发前选最低足够档位。档位控制交接详细程度，不改变授权或降低验收标准。所有档位都使用下面的必填字段；无适用内容写“无”并说明原因，不能留模糊占位符。

| 档位 | 适用范围 | 增补内容 |
| --- | --- | --- |
| Light | 独立只读摘取、明确的小文档修改 | 基础字段可每项一句 |
| Standard | 局部实现、故障定位、定向回归 | 依赖、接口约束、文件/资源负责人、已有检查的证据位置 |
| Strict | 已获授权的数据、权限、并发或跨模块高风险工作 | 授权依据、必须保持的不变量、失败与恢复方案、集成顺序、真实验收边界 |

## 派发模板

```text
Task / Level: 任务标识；Light / Standard / Strict
Goal: 需要交付的独立产物及用户可观察的结果
Acceptance: 可以核对的完成条件
Workspace: 绝对工作路径；分支/基线（若适用）
Inputs: 必要文件、事实、相关指令与待解决问题
Write scope: 允许修改的确切文件/目录；只读任务写“不得修改”
Non-goals / Boundaries: 不做什么；不得触碰的数据、接口和共享状态；默认禁止下级委派
Configuration: 当前工具支持的模型、推理强度、上下文模式及一句理由
Verification: 谁执行什么检查；已有结果位置与复用条件；未验证项目
Return: 使用下方统一回传格式
```

Standard 追加 `Dependencies / Ownership`；Strict 再追加 `Authorization / Invariants / Recovery / Integration`。若恢复涉及真实数据，不能把恢复方案当成执行授权。

文件范围不能只写“相关文件”。测试、文档或锁文件也是写入范围的一部分；需增加范围时先报告主智能体协调。没有独立分支时如实写共享工作区，不虚构隔离。

## 统一回传

```text
Status: DONE | DONE_WITH_CONCERNS | BLOCKED | NEEDS_CONTEXT
Result: 完成的结果，与 Acceptance 对照
Artifacts: 修改文件/只读发现位置；分支和提交（若存在）
Evidence: 实际执行的命令、目录、退出码、失败/跳过数量（适用时）及结果位置
Reused: 实际复用的证据来源、原执行时间和仍有效的依据；没有则写无
Limits: 失败、未验证项、具体疑点；缺少的信息或主智能体需处理的事项
```

- `DONE`：本任务全部必要条件满足，有证据且没有影响接收的疑点。
- `DONE_WITH_CONCERNS`：已产生产物，但存在验收缺口或疑点；不能表述为已通过。
- `BLOCKED`：已知权限、依赖、环境等障碍使任务无法继续，说明障碍和已有成果。
- `NEEDS_CONTEXT`：缺少明确的信息或决策，列出最小必要问题。

这是子任务回传协议，与宿主工具的任务/目标状态不同；不因此调用或改变宿主目标状态。无论何种状态，都保留可交接的成果与限制。
