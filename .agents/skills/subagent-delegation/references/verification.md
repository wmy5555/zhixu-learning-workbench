# 验证与接收

执行仓库 AGENTS.md 的完成条件；当前环境有 `lean-verification` 时使用它。本文件只补充委派交接，不复制一套独立验收门槛。没有该技能时仍按下述原则与仓库要求执行，不依赖某台电脑的绝对技能路径。

## 执行负责人

- 子智能体执行契约指定、与改动相称的检查，主智能体核对实际差异、覆盖范围、结果来源及集成影响。测试命令必须来自项目，不虚构 build/typecheck。
- 纯文档检查内容、引用和确有必要的现有校验，不新增只匹配措辞的测试。局部实现做定向回归；跨模块、数据或权限行为变更执行仓库要求的综合检查。
- 新文件须进入 Git 跟踪范围后再运行项目的跟踪文件检查；共享工作区的暂存由主智能体协调，不暂存他人的内容。
- 默认不新增独立审阅者。仅当用户或适用规则已要求时委派审阅；审阅者读契约、差异及已有证据，不重复执行测试/build/lint/typecheck。缺证据交执行负责人补充。

## 有效证据与停止条件

复用检查前核对原始结果、覆盖行为，以及代码、依赖、配置、运行环境和外部状态是否实质改变。SHA、rebase、新 PR、接手人或会话变化本身不是重测理由。输入不可核对、外部状态易变或用户明确要求重验时，执行必要检查。

一次约定范围的审阅，必要时一次针对修复的复审；新增真实问题继续处理，不能把次数用完当作通过。没有新增改动、失败或具体疑点时，不继续扩大检查。相同失败无新线索时停止重复执行并定位原因。

Click、RTK 等入口仅按当前会话的有效模式和项目规则使用；本技能不激活它们，不修改钩子、全局设置或复用策略。没有可核对的有效回执就不能声称复用。保留原检查命令、参数、退出码和诊断。

## 主智能体最终接收

1. 核对契约、允许范围和实际差异，确认没有覆盖用户改动、混入真实数据或改变未获授权的边界。
2. 对照验收条件核对已执行/复用证据；集成引入了新的影响时补相关检查，不机械重跑有效结果。
3. 按仓库要求检查相关 PR 普通评论、行内意见和审阅总结，保留未解决事项；执行当前提交 CI 与明确要求的外部验收。
4. 区分本地检查、模拟结果、模拟器/设备验收、真实供应商结果和 CI。构建成功不等于真实用户路径成功。
5. 由主智能体负责集成、合并及项目要求的后续检查。必要条件未满足时明确报告待验或阻塞，不把子智能体的 `DONE` 当成合并许可。

交付报告简述实际改变、实际执行、实际复用和未验证边界。不为每次委派建立专门报告或记忆文件；证据位置记录在现有任务/PR 即可。
