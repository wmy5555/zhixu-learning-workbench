# AI 整理失败修复

实际运行记录显示：连接测试在约 0.7 秒成功，但正式模型请求在 30001 ms 超时，之后又发起一次调用并被用户取消。另外一项任务多次因 SOURCE_CHANGED 失败，始终绑定修改前的原始资料哈希。不能把这些记录误判为密钥错误或断定供应商未收费。

修复：

- 模型生成独立使用默认 180 秒等待时间，Web 系统设置可配置 1–600 秒。其他能力的超时不扩大。
- 模型 POST 失败不再自动重试，包括超时和响应错误。供应商可能已执行/计费，需用户自行决定是否重试。
- 空正文、输出截断分别报明确错误，不自动重发。
- 用户明确重试旧任务时读取当前资料版本、丢弃不匹配的旧拆解快照，并复用已有同版本排队任务。不会自动恢复已取消的任务。

实测：当前已配置的 deepseek-flash 完成单次合成文本 JSON 整理，返回一个候选且字段类型正确，约 1.8 秒；输入 144、输出 175，共 319 token，金额未知。未发送真实资料，没有执行联网研究，不宣称整份真实资料的核验已经完成。

新增离线测试覆盖模型独立超时、不重复请求、空/截断响应和旧资料重试。供应商结构化能力说明参见 [DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/)。连接测试通过只能说明短请求通路可用，不能证明长资料在原有 30 秒限制内完成。

本次完整测试：60/60 通过，0 失败，耗时 6509.2506 ms。服务已重启应用修改，未自动重跑用户取消的任务。
