## 固定网页版本，明确选择后再同步

按所有者本轮明确要求，Android 固定使用本会话起点的网页版基线 `5e7bbd80c4f1d5e54e830f87ce09aca324d8141c`，叠加第一阶段 `ea0303aba16d081309a98df1810cc157735ebd12` 及后续手机自身改动。该快照保存于 `apps/android/web/`，来源与策略记录在 `apps/android/web-baseline.json`。Capacitor 8.5.2 只打包这个目录，不读取后续变化的 `public/`。

普通主分支提交、网页小改动和依赖 PR 不构成同步授权。网页版完成一次大版本更新后，先说明变更、手机适配成本与风险并询问所有者；得到明确确认后，才更新快照及基线记录。不得按定时任务、构建时最新 main 或隐式复制自动同步。这里的“大版本”指产品层面的较大更新，不擅自等同于某个版本号或批准规则。

| 改动 | 两端更新方式 |
|---|---|
| 颜色、字体、圆角、间距、阴影 | 网页改动留在 public；手机沿用冻结样式，获准同步后再适配 |
| 卡片、按钮、表单、详情抽屉 | 手机在快照中延续原有组件，独立验收触控行为 |
| 页面结构和导航 | 保留既定网页基线；手机能力接入独立演进 |
| 状态栏、启动画面、系统返回键 | 调整 Android 专用能力，并核对与网页交互的衔接 |

**已安装 App 不会自动更新外观。** 即使批准同步网页大版本，也需要构建并分发新的手机安装包。样机不提供在线热更新，不从电脑服务加载页面。

## 数据和能力边界

手机原文以本机 Markdown 文件为权威，SQLite 仅保存可从这些文件重建的索引。列表与搜索需要的派生数据损坏或丢失时，应能由有效 Markdown 重新建立；不能将索引中的旧内容反向覆盖原文。

这里的“SQLite 可重建”仅适用于本批原文样机。未来学习回答、任务检查点、历史与费用记录是独立的持久化资料，不能因为它们也存入 SQLite 就视作可丢弃索引。接入这些功能前，需要明确保存、备份、恢复和迁移规则。

资料保存在应用私有空间，不读取电脑的正式 Vault、数据库或凭据，不配置模型。通过 Android 系统文档选择器，仅访问本人逐次选定的文件或保存位置，不申请整个共享存储权限；文件提供方可能是本机或本人选择的网盘，不能将选择网盘导出称作资料仍只在本机。取消选择不更改资料。清除应用数据或卸载会失去未导出的内容；设备验收仍只用独立合成资料。

手机最多保存 100 份原文，每份正文最多 128 KiB、标题最多 200 个字符，历史总数最多 1000 条，备份包最多 32 MiB。达到限制会明确拒绝，不自动删除旧资料或历史。应用私有 Markdown 继续使用原有 v1 格式和目录，升级无需改写旧原文。独立应用标识 `io.github.wmy5555.zhixu.sharedtest` 保持不变，不覆盖 PR #47 的交换试验 App。

每次保存或合并备份前，会把完整资料和历史按实际 JSON 转义与 UTF-8 大小计算，超过备份上限便在写入前停止，避免“保存成功却无法备份”。第一阶段已存在的超限资料仍可读取，不会删减；此类旧库需要另行处理容量，不能保证整包导出。桌面普通文件导入继续采用原有 500000 字符正文上限，不套用手机容量。

## 文件、版本和备份怎样使用

1. **收集文件**：在“收集与加工”选择 txt/md 文件，系统窗口返回后先核对草稿与来源，再点“保存原始资料”。已有草稿会先询问是否替换。普通 Markdown 的头部也是原文，不冒充应用设置。
2. **导出单条原文**：在资料详情点“导出原文”。导出的 Markdown 包含 `zhixu-source-exchange` v1 受限头部和精确正文，保留平台、作者、网址、资料日期、定位与主题，不携带身份、权限或学习状态。手机与本次电脑文件导入可识别该格式；只建立本地参考原文，不自动运行 AI。私有 Vault Markdown、手机备份与电脑完整备份不是同一种文件。
3. **查看和恢复版本**：在资料详情进入“查看版本”，阅读旧正文后明确恢复。恢复使用当前版本标识，若期间已有修改则拒绝；恢复成功会把覆盖前内容留作历史，最初快照不变。
4. **导出手机备份**：在“系统”选择保存位置。包包含全部手机原文、来源、最初快照和编辑历史，不含索引、学习记录、附件、配置密钥或会话。只有输出流写入、刷新与关闭都完成才显示成功；失败文件不能用于恢复。
5. **恢复备份**：先选 JSON 包并预览新增、相同和冲突列表，勾选已审阅后再次确认。相同资料不重复添加，兼容历史补入；同一身份的正文、最初快照或同名历史不一致时，整份冲突资料跳过，保留手机当前内容。需要另一份内容时，可在原设备导出单条原文，再按新资料收集。

单条交换只支持完整的 HTTP/HTTPS 来源网址。旧资料中的其他网址不妨碍读取或手机备份，但导出原文时会提示先改正或清空该网址，不会静默丢弃来源。

预览凭据只在当前进程保留 5 分钟、单次使用；重新打开应用或资料发生变化后需重新预览。恢复先完整校验并暂存，持久提交标记落盘后才新增文件；中断后重开会幂等继续已提交计划，未提交暂存不生效。未知版本、非法字段、重复身份、路径穿越、损坏快照或超限包不进入写入阶段。恢复不会清空整个手机库，也不覆盖冲突内容。

升级验收需使用同一签名者的旧包和新包，实际覆盖安装并检查原文、来源、历史和主题。CI 可手动选择 `upgrade_baseline`，将固定第一阶段源码与新包用同一临时 debug 签名构建；密钥不上传。这只验证开发包升级路径，不能代替正式签名和商店发行验收。

实现和后续验收应遵守以下规则：

- 原文拥有稳定身份和内容版本；旧页面的保存不能静默覆盖较新的修改。
- 写入中断后保留可解释的状态；正文保存与索引更新出现分歧时，以有效 Markdown 为准恢复索引。
- 未支持的操作在界面禁用，设备接口同样拒绝，不能只靠按钮外观限制。
- 原文、用户回答、AI 建议与最终确认仍是不同记录，不能在适配时合并含义。
- 不以样机需要为由放宽网页版的会话、CSRF、外发权限或预算规则。

## 共用代码的分层方向

| 层次 | 职责 | 当前与后续处理 |
|---|---|---|
| 网页基线界面 | 页面、样式、组件、表单依赖、错误与空状态 | Android 在 `apps/android/web/` 延续已批准基线；通过能力说明控制可用入口 |
| 请求接入 | 页面请求、错误约定、上下文与设备分派 | Android 快照的 api 接入设备能力；电脑继续使用原有本地 HTTP 服务 |
| 共用业务规则 | 学习阶段、结算、任务状态、外发与预算规则 | 后续从现有业务模块逐项抽离；本批不复制一套简化学习规则 |
| 设备存储与系统能力 | Markdown、SQLite、凭据、文件选择、通知和后台调度 | 电脑和 Android 分别实现，遵守同一业务约定 |

Capacitor 负责网页与 Android 能力之间的调用，不会直接运行现有 Node.js 后端。`src/store.mjs` 的 Node 文件系统和原生 SQLite、`src/service.mjs` 的编排，仍需要按模块迁移。接口外形相同也不代表已经实现全部业务语义。

原有练习库切换、请求进行中保护、过期响应拒绝与错误信息，应保留在共用请求层；手机尚未支持的练习能力保持关闭。未来支持学习、AI 或后台任务时，再扩展设备能力，避免页面代码依赖某一个平台的数据库实现。

## 验证如何记录

### 构建样机

电脑网页服务仍按原有方式运行，不需要 Android 工具链。生成 Android 样机则需要 Node 24、项目指定 pnpm、JDK 21 和 Android SDK 36；Gradle Wrapper 固定为 8.14.3 并校验官方 SHA-256。

1. 在项目根目录执行 `pnpm install --frozen-lockfile`。
2. 执行 `pnpm android:sync`，将 Git 已跟踪的 `apps/android/web/` 文件复制到临时构建目录，并同步原生工程；新手机资源应先加入版本管理。当前 `public/` 变化不影响该安装包。
3. 进入 `apps/android/android`，Windows 执行 `./gradlew.bat :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug`，Linux/macOS 执行 `bash gradlew :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug`。
4. 应用 APK 位于 `app/build/outputs/apk/debug/`，设备测试 APK 位于 `app/build/outputs/apk/androidTest/debug/`。开发签名仅适合样机，正式发布签名另行管理。
5. 将两个 APK 安装到专用测试设备后，在项目根目录执行 `pnpm android:test-device --serial <设备序列号>`；ADB 未加入 PATH 时加 `--adb <adb完整路径>`。命令固定运行本项目设备测试，不安装或清空应用；ADB 退出正常但测试失败、没有成功总结或运行零项测试时，仍返回失败。

GitHub 的 **Android prototype** 工作流执行相同构建与静态检查，并保留 7 天的 `android-shared-ui-prototype` 产物。构建产物包含应用、设备测试安装包与 lint 报告，不包含用户资料或签名密钥。构建成功不代表设备测试已运行。

### 验收证据的含义

| 证据 | 能证明什么 | 不能代替什么 |
|---|---|---|
| 网页与接口回归、`pnpm verify` | 共用代码、既有电脑行为和已覆盖的接口约定 | Android 编译、原生文件系统与设备行为 |
| 原生桥的受控测试 | 参数处理、失败分支和指定存储规则 | WebView 实际调用、系统结束进程后的恢复 |

| 真机验收 | 指定设备和版本上的实际行为 | 未覆盖设备、系统版本或未来更新 |

本文件定义范围与验收标准，不登记未执行的成功结果。实际命令、提交、设备与未完成项由相应交付记录说明；没有 APK 或真机证据时，必须保留“待构建”“待设备验收”的状态。

### 第三阶段：本地学习使用与恢复（开发验收中）

在原文详情中选择手动整理，明确区分事实与个人观点。未经联网核验的事实保留阅读，但不开放学习；个人观点可以加入学习，在今日计划或条目详情开始练习。手机保存原始回答，结束后显示“尚未批改”，不会因点击结束而增加掌握度或计算新的复习间隔。自己的错题必须填写遗漏、改正和原因，与 AI 评价分开保存。

主题可以手工建立；系统页可调整每日分钟数、时区和安排时间，并恢复暂停的内容。安排时间仅用于本地计划，不代表已启用系统通知。四步本地引导根据真实保存、整理、作答和结束记录显示进度。

练习库仅预置一份明确标注的合成原文，不伪造作答或掌握记录。切换库会清空当前页面上下文；重置只清空练习库，正式原文和学习记录保留。正在保存时保留请求保护，旧库返回结果不会重新显示在新库。

正式库的原文继续使用第二阶段原文存储；学习 Markdown 与运行记录分别存入应用私有目录 `local-learning-v1/formal`，练习库使用 `local-learning-v1/practice`。文档采用不可变版本，索引、记录、设置和引导在同一次原子提交中发布；旧版本写入会被拒绝。资料仍不参加系统云备份或换机迁移，不新增权限。

**正式资料的完整备份需要两份文件：原文备份和学习备份。** 前者保留原文及来源版本，后者保留知识、错题、主题、回答、计划、学习文档历史及设置。学习备份预览不会写入；只允许恢复到完全空的对应库，或重复恢复完全相同的内容，不合并或覆盖不同的现有学习资料。设置或引导记录存在也属于非空。练习备份只能恢复到练习库。第三阶段暂不提供学习文档逐版本浏览，历史仍包含在学习备份中。

当前上限为每库 200 份学习文档、含历史最多 1000 个文档版本、每份正文 128 KiB、运行记录 8 MiB、完整学习备份 16 MiB。达到限制会报错并保留原状态。AI、批改、研究、输出、双端同步和托管链接重写尚未迁移；已保存的来源快照仅是抽取时原文，不是联网核验凭据。
