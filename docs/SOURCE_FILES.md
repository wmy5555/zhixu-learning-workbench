# 第一层附件与插图

## 使用范围

在「收集与加工 → 图片、PDF 和 Word」选择本地文件。每份最多 50 MB（50,000,000 字节），一次队列最多20份，同时上传2份，最多保留50份未保存回执。上传只到当前本机资料库；完成后仍需点击「保存已上传文件到第一层」。刷新或离开后，可在该资料库的收集页恢复未保存上传。没有云存储、目录导入、远程URL抓取或全页粘贴监听。

这里的MB按十进制计量，恰好50,000,000字节可导入，多1字节拒绝。选择器、HTTP二进制读取、暂存与磁盘读取、v2原件解码共用该上限。TXT/Markdown正文导入仍遵守既有500000字符及2 MiB读取保护；DOCX提取也仍受下述独立解析与字符限制，50 MB原件可保存不保证其内容均可转换。

系统未提供具体 MIME 或只报告 `application/octet-stream` 时，文件选择器按已支持的扩展名识别；服务端仍检查扩展名、MIME、文件头与大小，不能凭扩展名绕过内容校验。

| 格式 | 第一层阅读 | AI与第二层边界 |
|---|---|---|
| PNG、JPEG、GIF、WebP | 本地图片预览和原件下载；单边不超过16000、总像素不超过4000万 | 不OCR，不送图片给AI，不直接整理为知识 |
| PDF | 同源新标签交给浏览器PDF查看器；可下载 | 不提取文字、不OCR、不拆解、不直接整理为知识 |
| DOCX | 原件下载及本机提取文字；文本和原件哈希关联 | 核对提取文字后显式提交既有AI流程，仍受资料外发许可、供应商和预算限制 |
| DOC | 旧版二进制Word原件下载 | 不转换、不拆解；可用受信任编辑器另存DOCX后导入 |
| UTF-8 TXT / Markdown | 沿用文字导入与原文流程 | 沿用既有操作与许可 |

当前Word转文字能力覆盖DOCX的有限文字提取，旧DOC自动转文字仍是未实现需求。现有Mammoth入口读取DOCX ZIP，不能解析旧DOC的OLE正文；用户在受信任编辑器另存DOCX是现有可行步骤，程序不自动执行Office或新增系统转换器。

不接受HTML、SVG、宏格式DOCM、模板或音视频。扩展名、提供的MIME、文件头及图片尺寸同时校验；这不是杀毒或完整格式认证。DOC的OLE/Word流标识检查只决定是否可按旧Word原件保存，不保证文档可打开。PDF由浏览器处理，损坏文档可能不能显示；程序不自行运行其中脚本。下载后在外部软件打开的安全性不属于应用预览保证。

DOCX使用 `mammoth@1.13.0` 的 `extractRawText({buffer})`，不调用HTML转换、Office、CLI、宏或嵌入脚本，不启用外部文件访问。成功仍标为**部分覆盖**：图像、图表、公式、修订、页眉页脚、嵌入对象和版式不保证覆盖；扫描图像不能靠OCR补齐。通过文件头校验的DOCX若为空文本、损坏、ZIP加密/安全拒绝、超时或资源异常，会保留原件并显示原因，不提交AI。密码保护且采用OLE封装的DOCX不满足ZIP文件头要求，在导入入口明确拒绝，用户原文件不被改动。超过500000字符会截断并提示。正文补充说明和首次提取文本分开保留；AI拆解/结构分析使用提取文本，编辑补充说明不会静默替代提取结果。

转换使用独立worker，最多2个，10秒超时，V8老生代96MiB/新生代16MiB/栈4MiB；worker不是操作系统级沙箱，内存限制不涵盖全部Buffer/native分配。转换前逐项检查ZIP路径、重复项、加密、宏/ActiveX，最多2000项、单项10MiB、解压总量30MiB，并实际读完各项验证展开长度。不安装系统级转换器。

拆解、逻辑分析及手动整理入口重新计算提取文字SHA-256，与首次保存的`textSha256`核对；模型提示构造时同样检查。缺失或不匹配时拒绝加工，提示核对外部编辑、从可信版本恢复记录，原件和当前文字均不覆盖。这是文本一致性检查，不是数字签名；不能证明同时改写文字和校验值的记录来自转换器，也不会每次加工重新提取原件。

## 插图与编辑器接口

原始资料详情的「编辑原始资料 → 插入本地图片」提供同一上传器。每次编辑最多绑定20张，每份资料累计最多100张。选图后插入 `![文件名](../.zhixu-attachments/<sha256.ext>)`；保存正文时同时提交上传回执及当前 `expectedHash`。有外部修改则拒绝保存，让用户合并；不会覆盖原文。第二层不提供图片绑定。

`public/source-files.mjs` 导出 `createFilePicker(input, {imagesOnly,onUploaded,onRemoved})` 与 `imageReference`。上传回执含 `id`（上传UUID）、`attachment`（稳定内容ID、名称、MIME、大小、SHA-256、kind/format）与预分配 `noteId`。预分配ID不证明绑定完成。

**暂存图片没有同源 displayUrl**；上传器仅用本机blob显示临时预览。其他编辑器在保存前保留源码引用，不猜未存在的预览路由。`PUT /api/notes/:id` 同时传 `attachmentUploadIds` 与 `expectedHash`，成功后才可使用 `attachmentUrl(noteId, attachmentId)`。展示路由只允许当前笔记已经绑定的附件，并沿用当前练习/正式库和会话。删除队列项只撤销该次待保存回执，不删除共享字节或其他笔记引用。

## 持久化、去重与备份

附件原字节在当前Vault的 `.zhixu-attachments/`，按SHA-256及规范扩展名存放；笔记frontmatter保存原名、来源描述和提取记录。路径不使用用户文件名，不跟随附件目录/文件符号链接；读取时检查类型、大小和哈希。相同字节的第一层文件导入返回已有资料，保留原资料的标题与隐私选择；同名不同字节仍是不同资料。图片插入可以复用字节，但每个回执只能绑定一份笔记。

暂存/已绑定/已撤销回执持久化于当前SQLite，重试同一上传UUID不能替换字节。提交过程中撤销会阻止创建笔记；已保存后重试不会重复新增，被删除的已保存资料也不会因旧回执复活。正文编辑仍按原有版本快照保留。

每个Vault的附件目录最多256 MiB逻辑字节、1000个文件；包括暂存、已绑定、撤销、未引用原件和残留临时文件。新上传和恢复增补共用此检查，恢复在写入前检查整批缺失原件。到达容量时拒绝新增，**不自动删除任何文件**；已有字节仍可读取、去重绑定和恢复。累计上传回执最多5000条（包括撤销/已绑定），不因移出队列释放；达到后已有待保存回执仍可完成，原回执重试保持原语义。需要更多容量时，先完整复制Vault和运行数据，再使用独立资料库或由维护者评估调整；当前没有自动回收或清空回执功能。

无附件仍导出v1 JSON；笔记或历史有受管理附件时为v2，按内容ID去重并包含完整原字节，恢复前验证列表、哈希、MIME与大小，校验通过后只增补缺失字节。v1继续可恢复；旧程序不认识v2，不能用旧程序恢复含附件包。v2序列化包上限80 MB（80,000,000 字节），超限明确报错，需复制整个Vault与应用数据，不生成缺件包。外部放入Vault的未管理文件和Obsidian配置仍不进入JSON。

50 MB原件的base64长度为66,666,668字节，80 MB包上限包含编码、元数据和JSON开销；恢复请求单独允许80,001,024字节，给backup/preview/token包装保留1024字节。其他普通JSON接口保持原50 MiB请求上限。一个50 MB原件已完成v2往返；多个大原件使整包超80 MB时仍全部拒绝，不拆包或遗漏文件。旧版10 MiB单件或49 MiB备份限制的程序可能拒绝这些新增大文件，回退应保留新原件与备份。

导出先用每个原件的stat大小、base64展开量及JSON/元数据开销估算；预计超限时不读取或编码任何附件。读取后仍校验哈希，并保留最终序列化的精确80 MB检查。允许范围内的导出仍在内存构造，尚非流式备份；目录逻辑配额也不是操作系统磁盘隔离。单服务写入路径受限，其他本地程序、并发写进程或检查后的本地路径替换仍不具备原子隔离保证；未据此宣称已存在可利用的路径竞争漏洞。

暂存回执不导出，恢复不接受伪造回执。删除笔记、撤销上传与恢复失败均不物理清除附件；历史或其他笔记可能仍引用它们，暂不自动垃圾回收。仅暂存且从未绑定的文件不在JSON中。若Markdown恢复失败，已增补的字节可能作为未引用附件留下；既有原件不覆盖、不删除。恢复前快照沿用现有机制，不代表未合并的备份可靠性改进已纳入。

## 验证与已知边界

50 MB调整补充回归：精确50,000,000字节合成PDF经HTTP上传、绑定、同源预览读取、v2导出、跨HTTP预览恢复及确认恢复、重启后哈希核对；50,000,001字节上传及恢复均拒绝且零新增原件/资料。真实临时文件写入后模拟磁盘安装失败、中断请求，均不留临时文件或回执。大于旧10 MiB上限的12 MiB级DOCX仍可提取正文，单项展开11 MiB的DOCX仍拒绝转换、保留原件且禁AI；worker与ZIP限制未放宽。超备份上限的8份各8 MiB文件仍在读取原件前被拒绝。附件回归27/27及完整pnpm verify 764/764通过，0失败/取消/跳过。

独立普通Chrome另选本机中文路径下扩展至50,000,000字节的公开PDF样本，正常暂存、刷新恢复保存；多1字节的样本在选择器拒绝，未新增回执。原件数量、大小与SHA-256经只读核对，零AI任务。旧连接超时未产生回执，随后独立配置成功；不将连接故障描述为产品失败。此项覆盖页面与服务端大小边界，所有浏览器对50 MB文件的视觉渲染性能仍取决于浏览器和内容。

基于657ef2c的新隔离预览，以独立普通Chrome配置从OneDrive内含中文目录、空格和中文文件名的位置选择公开DOCX/PNG/PDF/DOC；四份均暂存，刷新后逐份恢复保存。只读核对四个原件SHA-256与所选文件一致，均为仅本地第一层资料，零AI任务。DOCX提取表格正文；DOC显示暂不转换且加工入口禁用。选择的是本机已具备字节的公开文件，OneDrive仅云端占位文件未验收。

50 MB调整前的预览另设默认容量样本库：实际目录268435456字节、1000个文件及累计5000回执，普通选择上传均被拒绝；满256 MiB仍可复用已有DOCX，满5000回执仍可恢复保存既有PNG。5份各8 MiB的公开PDF扩展容量样本导出被49 MiB预估限制拒绝；20份公开样本v2包在满1000文件库预览恢复也被拒绝。只读核对目录数量、逻辑字节、回执与笔记及既有原件哈希，拒绝路径未新增资料或附件。容量目录和回执为主动构造的隔离夹具，不代表用户真实库验收。

页面检查发现并修复了FilePond隐藏具体服务端原因的问题：选择器下方显示失败文件名和原因，使用纯文本；多个错误分别保留，重试或移除一项只清除该项提示。容量已满时按提示完整备份和评估容量，重试不同文件不会释放原件或历史。

验收使用随机临时目录与合成或公开样本，无真实用户文件、模型调用或付费操作。自动回归覆盖原件字节、重启、去重、第一层限制、DOCX正常/空/损坏/宏/加密/展开超限、转换超时、路径/MIME/尺寸、撤销重试、版本冲突、插图历史、备份恢复及HTTP会话/CSRF/预览响应。

公开 DOCX 对照确认：表格、列表、文本框与 Strict 格式可提取正文；脚注、尾注和批注内容会遗漏，已补入转换提示，不能将部分覆盖视为完整语义。20份公开文件经过API暂存重启、保存、v2备份和空库恢复，原件逐字节与提取记录一致，损坏备份被拒绝。该结果不代表所有 Word 格式都已验收。

真实 Chrome 的普通受控链接已显示公开 `tracemonkey.pdf` 正文、缩略图与 `1 / 14` 页。普通页面点击「下载原件」后，Chrome下载记录为完成，实际落盘文件为1,016,315字节，SHA-256为`3662ff519e485810520552bf301d8c3b2b917fd2f83303f4965d7abed367e113`，与公开原件及受管理附件身份一致。扩展主动下载接口曾因认证上下文报错；这与普通页面下载的结果分开记录，没有放宽会话或附件安全头。

另有定向负向回归覆盖：跨站二进制上传被拒绝、暂存未绑定与跨笔记附件不可读、下载仍需会话、练习与正式库的回执和原件相互隔离、未完成模型连接测试时练习写入仍被拒绝；同长度字节篡改使读取与备份失败，笔记保持不变，恢复可信原字节后可继续读取。这些是本执行者的边界测试，不能替代独立安全审阅报告。

生产依赖高危审计无high/critical；Mammoth的CLI传递依赖 `argparse > sprintf-js@1.0.3` 有moderate [GHSA-hp3w-g68c-fv3c](https://github.com/advisories/GHSA-hp3w-g68c-fv3c)。公告描述可控精度格式串触发未捕获 RangeError，当前未列出修复版本。已核对锁定包的入口、CLI与rawText源码，并实际加载Mammoth确认未加载argparse/sprintf-js；当前worker不调用CLI或接收sprintf格式串，因此此路径未发现告警触发点。这是当前调用路径判断，不等于完整安全审查；该传递依赖仍安装在本机，未伪称零漏洞。若以后调用CLI或更改路径，必须重新评估。

真实复杂Word的完整语义、密码文件、超大文档、所有浏览器PDF实现和生产供应商调用未验收。新功能只在网页版实施，Android冻结快照保持原样。用户真实资料仍待验收；独立合成页面不等于已更新现有4318服务。

回退应用代码可切回本功能之前提交；附件与v2备份应保留，旧版本不能完整使用这些资料。不要以删除新附件目录或覆盖生产数据作为回退方法。
