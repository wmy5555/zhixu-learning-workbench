# 第一层附件与插图

## 使用范围

在「收集与加工 → 图片、PDF 和 Word」选择本地文件。每份最多 10 MiB，一次队列最多20份，同时上传2份，最多保留50份未保存回执。上传只到当前本机资料库；完成后仍需点击「保存已上传文件到第一层」。刷新或离开后，可在该资料库的收集页恢复未保存上传。没有云存储、目录导入、远程URL抓取或全页粘贴监听。

| 格式 | 第一层阅读 | AI与第二层边界 |
|---|---|---|
| PNG、JPEG、GIF、WebP | 本地图片预览和原件下载；单边不超过16000、总像素不超过4000万 | 不OCR，不送图片给AI，不直接整理为知识 |
| PDF | 同源新标签交给浏览器PDF查看器；可下载 | 不提取文字、不OCR、不拆解、不直接整理为知识 |
| DOCX | 原件下载及本机提取文字；文本和原件哈希关联 | 核对提取文字后显式提交既有AI流程，仍受资料外发许可、供应商和预算限制 |
| DOC | 旧版二进制Word原件下载 | 不转换、不拆解；可用受信任编辑器另存DOCX后导入 |
| UTF-8 TXT / Markdown | 沿用文字导入与原文流程 | 沿用既有操作与许可 |

不接受HTML、SVG、宏格式DOCM、模板或音视频。扩展名、提供的MIME、文件头及图片尺寸同时校验；这不是杀毒或完整格式认证。DOC的OLE/Word流标识检查只决定是否可按旧Word原件保存，不保证文档可打开。PDF由浏览器处理，损坏文档可能不能显示；程序不自行运行其中脚本。下载后在外部软件打开的安全性不属于应用预览保证。

DOCX使用 `mammoth@1.13.0` 的 `extractRawText({buffer})`，不调用HTML转换、Office、CLI、宏或嵌入脚本，不启用外部文件访问。成功仍标为**部分覆盖**：图像、图表、公式、修订、页眉页脚、嵌入对象和版式不保证覆盖；扫描图像不能靠OCR补齐。通过文件头校验的DOCX若为空文本、损坏、ZIP加密/安全拒绝、超时或资源异常，会保留原件并显示原因，不提交AI。密码保护且采用OLE封装的DOCX不满足ZIP文件头要求，在导入入口明确拒绝，用户原文件不被改动。超过500000字符会截断并提示。正文补充说明和首次提取文本分开保留；AI拆解/结构分析使用提取文本，编辑补充说明不会静默替代提取结果。

转换使用独立worker，最多2个，10秒超时，V8老生代96MiB/新生代16MiB/栈4MiB；worker不是操作系统级沙箱，内存限制不涵盖全部Buffer/native分配。转换前逐项检查ZIP路径、重复项、加密、宏/ActiveX，最多2000项、单项10MiB、解压总量30MiB，并实际读完各项验证展开长度。不安装系统级转换器。

拆解、逻辑分析及手动整理入口重新计算提取文字SHA-256，与首次保存的`textSha256`核对；模型提示构造时同样检查。缺失或不匹配时拒绝加工，提示核对外部编辑、从可信版本恢复记录，原件和当前文字均不覆盖。这是文本一致性检查，不是数字签名；不能证明同时改写文字和校验值的记录来自转换器，也不会每次加工重新提取原件。

## 插图与编辑器接口

原始资料详情的「编辑原始资料 → 插入本地图片」提供同一上传器。每次编辑最多绑定20张，每份资料累计最多100张。选图后插入 `![文件名](../.zhixu-attachments/<sha256.ext>)`；保存正文时同时提交上传回执及当前 `expectedHash`。有外部修改则拒绝保存，让用户合并；不会覆盖原文。第二层不提供图片绑定。

`public/source-files.mjs` 导出 `createFilePicker(input, {imagesOnly,onUploaded,onRemoved})` 与 `imageReference`。上传回执含 `id`（上传UUID）、`attachment`（稳定内容ID、名称、MIME、大小、SHA-256、kind/format）与预分配 `noteId`。预分配ID不证明绑定完成。

**暂存图片没有同源 displayUrl**；上传器仅用本机blob显示临时预览。其他编辑器在保存前保留源码引用，不猜未存在的预览路由。`PUT /api/notes/:id` 同时传 `attachmentUploadIds` 与 `expectedHash`，成功后才可使用 `attachmentUrl(noteId, attachmentId)`。展示路由只允许当前笔记已经绑定的附件，并沿用当前练习/正式库和会话。删除队列项只撤销该次待保存回执，不删除共享字节或其他笔记引用。

## 持久化、去重与备份

附件原字节在当前Vault的 `.zhixu-attachments/`，按SHA-256及规范扩展名存放；笔记frontmatter保存原名、来源描述和提取记录。路径不使用用户文件名，不跟随附件目录/文件符号链接；读取时检查类型、大小和哈希。相同字节的第一层文件导入返回已有资料，保留原资料的标题与隐私选择；同名不同字节仍是不同资料。图片插入可以复用字节，但每个回执只能绑定一份笔记。

暂存/已绑定/已撤销回执持久化于当前SQLite，重试同一上传UUID不能替换字节。提交过程中撤销会阻止创建笔记；已保存后重试不会重复新增，被删除的已保存资料也不会因旧回执复活。正文编辑仍按原有版本快照保留。

无附件仍导出v1 JSON；笔记或历史有受管理附件时为v2，按内容ID去重并包含完整原字节，恢复前验证列表、哈希、MIME与大小，校验通过后只增补缺失字节。v1继续可恢复；旧程序不认识v2，不能用旧程序恢复含附件包。v2序列化包上限49 MiB，超限明确报错，需复制整个Vault与应用数据，不生成缺件包。外部放入Vault的未管理文件和Obsidian配置仍不进入JSON。

暂存回执不导出，恢复不接受伪造回执。删除笔记、撤销上传与恢复失败均不物理清除附件；历史或其他笔记可能仍引用它们，暂不自动垃圾回收。仅暂存且从未绑定的文件不在JSON中。若Markdown恢复失败，已增补的字节可能作为未引用附件留下；既有原件不覆盖、不删除。恢复前快照沿用现有机制，不代表未合并的备份可靠性改进已纳入。

## 验证与已知边界

所有验收使用随机临时目录与合成PNG/PDF/DOC/DOCX，无真实用户文件、模型调用或付费操作。自动回归覆盖原件字节、重启、去重、第一层限制、DOCX正常/空/损坏/宏/加密/展开超限、转换超时、路径/MIME/尺寸、撤销重试、版本冲突、插图历史、备份恢复及HTTP会话/CSRF/预览响应。

生产依赖高危审计无high/critical；Mammoth的CLI传递依赖 `argparse > sprintf-js@1.0.3` 有moderate [GHSA-hp3w-g68c-fv3c](https://github.com/advisories/GHSA-hp3w-g68c-fv3c)。当前rawText运行路径不载入CLI/argparse，不接受sprintf格式串；该传递依赖仍安装在本机，未伪称零漏洞。若以后调用CLI或更改路径，必须重新评估。

真实复杂Word的完整语义、密码文件、超大文档、所有浏览器PDF实现和生产供应商调用未验收。新功能只在网页版实施，Android冻结快照保持原样。用户真实资料仍待验收；独立合成页面不等于已更新现有4318服务。

回退应用代码可切回本功能之前提交；附件与v2备份应保留，旧版本不能完整使用这些资料。不要以删除新附件目录或覆盖生产数据作为回退方法。
