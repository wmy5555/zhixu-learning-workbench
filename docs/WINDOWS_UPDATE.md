# Windows 便携版增量更新

系统设置 → 软件更新 → 检查更新。只在点击时读取本机 `/updates/latest.json`，没有后台轮询、远程上传或自动运行程序；下载按钮只接受同源 `/updates/*.exe`。未配置更新目录时说明没有更新信息，不能据此声称已是最新。正式 4318 可提供本次下载，便携实例也可以直接运行已取得的更新 EXE。

本次支持 `2026-10-21` 的 `知序.exe`，原包 SHA-256 为 `082bd7451331a9f714b08599a4469a6a0b82d41ce4710b672dd9e9094253bfda`。目标为当前正式 4318 固定源码加软件更新入口，界面版本 `2026.10.23.1`。这不是独立安装器，必须先运行过旧 EXE。默认更新 `%LOCALAPPDATA%/ZhixuPortable/versions/cbedaeaebd14fa64a6ba`。自定义数据目录使用 `更新包.exe --data-dir "原数据目录"`。不能将此更新器用于 4318 源码服务。

先保存所有网页输入，再运行更新器并确认。它核对旧版每个程序文件及内嵌差异，复制未变化的文件，在相邻暂存目录应用新增与改动并校验完整目标。运行时沿用旧包，不随增量重复附带；新版本不再需要的旧文件不会进入新版。没有读取、复制、迁移或覆盖数据库、Vault、密钥和设置。程序文件被修改、缺失、目录经过联接或符号链接、版本不符时拒绝更新。

准备完成后，使用旧启动器既有的按数据目录隔离的命名事件请求优雅退出，并取得原单实例互斥锁。无法正常退出则不切换目录。旧程序改名为同级 `rollback-*`，新目录再改名为原缓存键；第二次改名失败立即还原。保留旧 `.complete` 键是兼容旧 EXE 的必要条件：下次仍双击原来的 `知序.exe` 即可打开新版，不会重新解压旧内容。再次执行同一更新器会校验目标并显示无需重复更新。

回退：在托盘退出便携版，将当前程序缓存目录改名留存，再将对应的 `rollback-*` 改回 `cbedaeaebd14fa64a6ba`。这是程序回退，不是资料备份或数据库降级方案；使用新版本产生资料后，不应假定旧版本支持新数据。更新准备失败的 `update-stage-*` 保留便于诊断，不会被当作可运行版本。

构建入口：`packaging/windows/build-update.ps1 -Source <干净固定源码> -BasePayload <旧包build/payload> -Output <全新输出目录>`。仅按 Git 跟踪的 `src/`、`public/` 和固定依赖构造目标，保留第三方许可；`update.json` 记录基线、目标与全部文件哈希，EXE 仅嵌入变化文件和清单。Node/.NET 编译器仅构建时需要。EXE 未做代码签名。

性能：日常页面没有更新轮询或自动检查；首次打开设置仅增加本地模块，只有用户明确点击才取一份小清单。更新期间才复制和校验程序文件，不对个人资料做扫描。无真实 AI 请求。
