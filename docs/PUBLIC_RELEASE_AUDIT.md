## 发现项：CI 测试密钥出现在历史日志

根因：CI 用 `randomBytes(32)` 为每个隔离 job 生成 `LEARNING_MASTER_KEY`，写入 `GITHUB_ENV` 后未注册遮蔽，后续步骤的环境摘要打印了值。全部 36 条命中均确认是这一路径，去重为 18 个 job 独立的临时随机值，没有其他类型命中。

这些值仅保护测试创建的临时数据库/虚构凭据，没有连接真实知识库，没有作为外部 API key 使用；测试清理及 job 结束后不再复用。**不是已确认的生产 Secret 泄露，本次没有需要撤销或轮换的真实凭据。** 不把它描述为扫描零命中。

修复：生成后先发送 GitHub Actions `add-mask` 指令，再写入 job 环境。新的 CI 日志必须实际验证为遮蔽状态。历史日志保留原样；本次不删除日志、改写历史或移动已有标签。未来扫描若发现真实 Secret，先按 SECURITY.md 处理撤销/轮换，不以删除文件代替事件处理。

修复实测：[审计 PR 的 CI #35518569317](https://github.com/wmy5555/zhixu-learning-workbench/actions/runs/35518569317) 四项全部成功；下载其全部 44 个日志文本，Windows/Ubuntu 环境值均显示遮蔽（含总日志和分步日志共 4 处），明文临时密钥 0 处，Gitleaks 复扫 0 命中。旧版本或旧 PR 的工作流内容不会被历史改写修复，重新运行旧版本时仍需注意此已知问题。
