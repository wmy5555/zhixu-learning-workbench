### 已观察到的关键结果

- 外部改动会在读取前重新扫描并更新关键词索引；外部改名保留 frontmatter 中的稳定 id。
- 同一 id 出现在两个文件时，两份文件都退出当前索引；移除重复文件后原文件恢复。格式错误文件也只隔离自身。
- 旧哈希的 Web 修改不会覆盖用户刚完成的外部编辑。删除会移除当前文件与检索片段，历史版本仍显式保留但不会回到默认搜索。
- 备份恢复保留学习会话与版本历史。虚构 API key 不出现在设置响应或备份中，本机 `secrets.enc.json` 不含明文；Windows 上本次写入为 DPAPI 密文。
- 今日学习清单在 10 分钟预算下只安排两个 5 分钟条目；重复生成没有增加第三条任务。相同答题 `requestId` 不会重复保存，服务重启后原回答仍在。
- 错题原答案、停用或被替代知识、草稿都未进入默认 RAG。仅本地资料在模型设置开启时仍未进入生成请求。
- 恶意导入文字中即使包含“调用接口、读取 token、删除笔记”等指令，也只作为 source 正文保存，没有创建任务、提案或额外笔记。
- 真实本地 HTTP 服务拒绝伪造 Host、跨 Origin、无会话读取和无有效 CSRF 的修改；恢复内容在预览后被改动时，确认 token 失效。

### 受控编排测试边界

`tests/pipeline.test.mjs` 使用带 `ORCHESTRATION_TEST_ONLY_NO_NETWORK` 标记的有界 `aiOverride`。它没有发出 HTTP 请求，也没有冒充真实模型或真实研究。固定返回值只用于观察服务端状态和权限编排，实际通过的行为包括：

- 获准外发的 source 经固定拆解和固定研究结果生成 candidate，候选条目保留原 source、测试 evidence source、证据角色和限制字段；用户随后主动晋级、作答、收到错误反馈、质疑错题，最后以自己的文字确认 integrated 笔记。
- 模拟研究失败时，已经生成的 candidate 保留 `researchLimitations`，不会进入今日题目或默认 RAG 答案。底层 source 改动后，旧 `processKey` 候选同样退出学习和回答材料。
- `dailyCallLimit` 与 `monthlyBudget` 的字符串输入会保存为数字；每日预算由 25 分钟降到 5 分钟后，只保留不超过 5 分钟的 pending 项，其余进入 `budget_deferred`。
- 即使库中存在 cloud 笔记且模型、嵌入开关打开，默认 hybrid search 和 ask 仍保持 local，不调用 mock embed/generate。只有调用方明确传入 `privacy:'cloud'` 才进入受控嵌入与生成分支。
- 模型返回不存在的 `citationIds`，或正文偷偷加入未检索的 `[bogus-id]`，都会以 `INVALID_CITATION` 拒绝且不保存 draft。AI 学习包引用不存在或不符合资格的 note id 也会失败，不生成报告。
- cloud 与 local 知识合并后，保留条目的隐私范围收紧为 local。
- 缓存研究结果只要仍含 `limitations`，下一次加工就会再次调用受控 research；不会把失败或证据不足缓存七天后直接复用。
- 已生成候选被用户通过 Web 修改，或正文从 Vault 外部修改导致 `generatedBodyHash` 不匹配时，重新加工不会覆盖正式正文和元数据，而是创建 pending proposal。只有用户接受提案后，新正文和候选元数据才写入；原版本继续留在历史中。

这些结果只证明固定输入下的程序编排和防护分支，不证明模型输出质量、在线研究真实性、同义召回效果或外部服务可用性。
