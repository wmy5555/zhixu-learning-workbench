# 本地检索与容量验证

关键词检索保持原来的规则：完整子串命中，或去重后的中文单字/英文数字术语达到原字符覆盖阈值。SQLite FTS5 使用内置 unicode61，将小写文本的一至三字符片段编码为普通索引词；它只筛选候选，再以字面子串核验和原分数排序。中文单字、双字、术语、嵌入英文型号、标点和非汉字查询无需依赖语言词典。相同分数按稳定 ID 降序确定顺序；保留现有语义最佳片段、RRF 融合及学习阶段加权。

每次仅为 8,192 个 UTF-16 字符生成临时片段词集合，按 7,168 字符推进；相邻块重叠 1,024 字符，覆盖最长 512 字符查询的小写展开和跨块命中。候选按笔记身份去重，全文字面核验仍使用完整正文；不截掉尾部、不限制新增资料的原有 5 MB 文件边界。脏索引逐条迭代，不先载入全部待更新正文。投影布局版本变化时本地重建派生表，保留 Markdown、学习记录及既有向量。

Markdown 是内容权威，全文投影和持久脏记录位于原 SQLite 中，没有独立索引库。数据库触发器在资料增删改的同一事务登记待同步身份；下一次检索或启动更新投影，失败回滚并保留待处理记录。重复 ID、无效 YAML、删除、恢复和改名继续使用原扫描隔离规则。全文重建不删除或重算 `index_chunks` 的向量，原有按片段正文复用的机制保持。

主题、学习阶段等元数据变化仍更新全文投影中的摘要、筛选字段和版本。在同一同步事务内，只有小写规范化后的标题与正文发生变化时才重建分段词；删除和显式重建仍清理旧分段，不增加跨请求缓存。

每次检索枚举受管理文件并比较设备、文件身份、大小、mtime/ctime 纳秒指纹，只重读变化文件；不依赖可能丢失或迟到的文件监听事件。启动、明确全量校对，以及距离上次完整扫描超过 60 秒后的下一次同步，均重新读取并哈希校对全部 Markdown。正常外部保存可在下一次检索发现；人为同时保留全部文件指纹的修改由完整校对兜底，不能声称即时检测。内部写入仍保留原文件哈希冲突保护。

检索先筛类别、状态、主题、来源和日期，再排名和分页。当前页才反序列化完整笔记；Web 列表只返回最多 600 字的命中上下文，打开详情才返回全文。位置包含正文 UTF-16 偏移、行列、最近章节、路径及版本哈希；标题命中单独标注。语义命中没有字面词时定位到实际最佳向量片段。页面会拒绝把旧版本位置用于新正文。

分页使用完整排序值与唯一 ID 的复合游标，并绑定查询、筛选、页大小、资料库实例和索引修订。最多保留 8 个、每个 5 分钟的内存排序快照；后续页复用语义结果，不再次请求查询向量。资料变化、切库、重启、快照过期或被淘汰时返回 `SEARCH_CURSOR_STALE`，页面保留已读内容并提供重新检索。每页 1–50 条，检索词最多 512 个 UTF-16 字符。未承诺跨版本快照或无限期继续分页。

在「检索与发现」检索并展开「查看这次检索怎样工作」可读诊断：

- `elapsedMs` 从服务开始、同步之前计时；`phases` 分别包含同步、索引更新、关键词、语义、排序和当前页正文读取。
- `sync.checkedFiles/readFiles/mode` 区分指纹检查与实际正文读取；`indexUpdated` 统计更新的索引身份，`bodyReads` 是当前页笔记的读取次数，不包含校验依赖引用。
- `httpPrepareMs` 从收到 HTTP 请求到响应准备，尚未包含 JSON 编码/传输；浏览器 `clientRoundTripMs` 包含请求、传输和解码，`clientToDomMs` 到结果 DOM 构建完成，不宣称测到浏览器绘制。

「系统 → 诊断 → 重建本地全文索引」执行本地完整校对和全文重建，不调用模型。原「全量重建索引」是已有语义索引任务，可能调用嵌入服务；两者各自保留原会话和 CSRF 要求。

## 重现与边界

```sh
node scripts/search-benchmark.mjs 1000,10000 .tmp/search-benchmark.json
node --test tests/search.test.mjs
pnpm verify
```

基准仅生成随机临时目录中的 1,000/10,000 条合成资料，包含 396,012 个 UTF-16 字符的单篇长文；记录首次查询、三轮热查询、独立冷进程启动和检索、完整分页及召回/摘录检查，结束后删除该次合成库。冷进程不代表操作系统磁盘缓存已清空。报告、临时库和截图不提交；机器负载会影响绝对耗时。基准数据、容量结果及具体运行证据见 [测试结果](TEST_RESULTS.md)。

检索回归另覆盖旧规则召回对照、同尺寸外部改动并恢复 mtime、移动/重复/无效属性隔离、内部保存、版本恢复、向量复用、索引事务失败/重试、子进程未正常关闭后恢复、完整过滤和稳定分页、两库身份、语义分页不重复嵌入、HTTP 摘录与详情、UI 失败/迟到响应。均为合成资料或受控适配器，未调用真实供应商。

本次优化的是 `search` 及发现页。资料库分组、启动 bootstrap、学习/关系业务仍有既有整库读取，不把局部结果当作整个应用的容量保证。每次检索仍有 O(文件数) 的本地指纹检查，宽泛单字可能召回大量候选；首次构建全文投影增加启动时间和磁盘占用。语义向量扫描和外发校验成本未在纯关键词基准中测量。
