# 原设计对齐与修复记录

本轮把审阅发现的九项主要差距接成可操作的流程。保留三层内容的含义：原始资料、经过整理并保留依据的材料、用户自己确认的理解。没有强行改成三个文件夹，也没有把 AI 评价当成掌握证明。

## 逐项结果

| 审阅发现 | 修复后的行为 | 操作位置与验证 |
|---|---|---|
| 阶段存在，但缺少持续判断 | 根据学习目标、主题成员、已结束练习、实际采用、研究限制生成带理由的建议。需要用户接受；忽略会记住，证据变化后可重新建议。 | 知识库 → 知识使用建议；生命周期及集成测试 |

| 四档深度没有改变练习 | 了解、能找到、能解释、能迁移分别使用不同问题和提示；批改带本次目标、近期回答和专项误解。独立作答、提示、跨日表现分别保存。 | 学习与错题；四深度及上下文测试 |

## 结算与建议的明确含义

“结束练习”保存这次练习的结果；“确认个人理解”保存用户自己写下的表达。没有反馈时可以保存理解，但不会凭空生成批改结果或把待反馈练习标为完成。争议反馈保留记录，不增加复习间隔。

初次独立练习先安排近期复习。只有另一天、到期后独立回答，才增加间隔；使用提示或出现错误会缩短间隔。主题进度表示已经留下练习结束或理解确认记录，不表示永远掌握。

核心知识建议采用可解释的保守起点：最近一次用户确认理解之后，至少三个不同当地日的独立解释/应用练习、至少两个不同当地日的实际输出采用，并且已有用户确认的理解。这个阈值是产品规则，不是经过科学验证的掌握评估；最终仍由用户决定。重学建议来自最近的错误或提示记录。没有实际采用时不会用浏览次数代替。

## 同时修正的其他问题

- 合并后的知识可从每份原始资料回到同一个条目，不会只挂在第一个来源下。
- 批量研究按最多三项一组安排双向检索；预算不足的尾项明确保留为未覆盖，重试复用已完成项，不能把只评价过尾项写成专门检索过。
- 单份原始资料可设置下一次成功核验后的有效天数（1–365，默认 30）；不会仅因修改天数就延后现有过期知识。
- 取消“实际采用”勾选会撤回对应使用证据；重复保存草稿不会制造新的采用日期。
- 自动全局发现只做本地检查。手动 AI 探索受单次与全局预算限制；预算不足仍保留已有本地结果和未完成原因。
- 管理链接涉及本地笔记时收紧外发权限；目标后来改为本地时，上游资料即使还未同步链接也不得外发。人工改过管理区块时停止自动覆盖。
- 使用指南和 README 不再把历史“未配置模型”的快照描述为当前用户配置。2026-09-20 的真实合成调用记录仍有明确范围，见加工修复记录。

## 验收范围

新增的学习、存储、生命周期、研究覆盖、界面交互和异步隐私测试均使用隔离的合成资料。未读取或迁移真实 Vault，未修改真实凭据，未启动或停止用户日常服务，未发起付费模型、搜索或向量请求。

本地 `pnpm verify`：164 项通过、0 失败、0 跳过；语法/仓库规则及 20 条合成检索质量检查通过。`pnpm audit --prod --audit-level high`：未发现已知漏洞。

隔离浏览器验收实际操作了误解专项作答、等待模拟反馈、结束练习、重排主题并保存、查看下一项、接受参考建议以及展开来源证据。检查了 1280 像素桌面及 390 像素窄屏、日夜模式，未发现横向溢出，浏览器无脚本错误。模拟反馈在页面明确标识，不能视为真实供应商成功。

真实材料的教学合理性、非显然关系价值、供应商完整在线闭环、大库长期运行和 Obsidian 客户端实际显示仍不能由上述测试代替。

JSON 备份的范围保持为 Markdown、运行记录与历史版本；图片、PDF、音频和 `.obsidian` 需另行备份整个 Vault。这是明确保留的产品边界，不将文本备份包装为全部附件备份。

## 维护结构

学习、主题和复习规则集中在 `src/learning.mjs`；带依据的阶段建议集中在 `src/knowledge-lifecycle.mjs`。`service.mjs` 继续负责跨模块编排，Web 和 MCP 共用服务，`store.mjs` 负责文件权威、镜像、版本和索引。运行记录仍需正常备份，删除数据库只能重建内容镜像，不能凭空恢复学习历史。
