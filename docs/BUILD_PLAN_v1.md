# 个人学习与知识管理 Web App 施工计划书

**版本：1.0 ｜ 日期：2026-09-20 ｜ 用途：交付开发模型独立设计与实现**

> 产品目标：把日常接触的碎片信息，转变为可追溯、可学习、可复习、可关联、可输出的个人知识。日常操作全部在一个浏览器应用中完成；知识文件兼容 Obsidian；AI 通过 API 参与加工、教学与检索，并通过 MCP 向其他 AI 应用开放受控访问。

本文件固定产品目标、关键行为、数据边界与验收条件，不固定技术栈、数据库表结构、接口签名、具体模型、页面布局和算法参数。开发模型可以自行优化实现，但不能以“简化”为由省略学习闭环、联网核验、知识晋级、关联发现、Obsidian 双向读写或真实 MCP 接入。

## 1. 产品边界与默认形态

### 1.1 面向谁，解决什么问题

用户有高中毕业程度的通用知识，希望大量保存抖音内容、AI 对话及其他文本资料，长期消化理解，并在写作、项目和决策时重新找到相关知识。用户同时希望借这个项目，从零理解 RAG、MCP 等技术。

系统不以收藏数量、笔记数量、链接数量或连续打卡天数作为主要成功指标。优先观察：能否找到有用材料、能否解释和应用知识、错误是否得到纠正、内容是否实际用于输出，以及学习负担和运行成本是否可控。

### 1.2 默认部署与操作方式

默认采用**本地优先、单用户、中文界面的 Web App**：浏览器是统一界面，本地后端负责文件、任务、检索与外部 API。首次安装与启动可以使用安装包或脚本；配置完成后的输入、编辑、学习、复习、维护和设置均须在 Web 内完成，不要求用户日常打开终端或 Obsidian。

“一个 Web 窗口”不意味着必须把所有计算放进浏览器。浏览器的本地文件访问有授权与兼容性边界，因此本计划默认由后端访问用户指定的 Vault，而不把纯前端文件系统能力作为唯一基础。[1](https://developer.mozilla.org/en-US/docs/Web/API/File_System_API)

Obsidian 的 Vault 是保存 Markdown 等文件的本地文件夹，官方支持外部编辑器修改笔记并刷新变化。因此，本程序应直接兼容这些文件，而不是依赖 Obsidian 常驻或特定社区插件。[2](https://help.obsidian.md/Files+and+folders/How+Obsidian+stores+data)

远程部署、手机同步、多用户协作不是首轮完整交付的必要条件。若采用远程部署，必须明确 Vault 实际位于哪里、如何获得授权访问，以及定时任务在哪里运行，不能假设云端自动拥有本地文件访问权。

### 1.3 范围控制

必须交付本计划描述的完整功能，但可先做简单可靠的实现，再增强算法。文本粘贴、批量文本/Markdown 导入是输入底线；自动抓取抖音视频、音视频转录、OCR、浏览器扩展可作为后续扩展，不得成为主流程的前置依赖，也不承诺任意链接都可抓取。

系统只处理用户提供或明确授权取得的内容，不假定能自动读取其他 AI 产品的历史聊天。复杂图数据库、完整 GraphRAG 框架、多个自治 Agent、3D 知识图谱均不是必须采用的技术。

## 2. 总体流程与三层知识结构

```text
文本资料 / 抖音转录 / AI 对话 / 网页摘录
                    ↓
第一层：原始资料，保留原文、来源和定位信息
                    ↓
AI 拆解 → 区分事实与观点 → 对事实联网核验、保留反证
                    ↓
第二层：结构化材料与候选知识
          ├─ 仅作为参考资料
          ├─ 留在候选池，等待价值显现
          └─ 晋级进入学习队列
                    ↓
按主题与前置知识组织学习包
                    ↓
主动回忆 → 自己解释 → AI 追问 → 反馈与修正
                    ↓
第三层：经用户确认的个人理解与综合主题笔记
          ↕                ↕                 ↕
    间隔复习/错题库     关联发现与认知更新     检索/问答/输出
                    ↓
      同一知识服务供 Web 与 MCP 使用
```

**第一层：原始资料。** 保存实际收到的文本、必要附件及来源位置，不用摘要替换原文。AI 对话应尽量保留角色、上下文和轮次；来源不完整时如实缺省，不能编造作者、日期或链接。自动处理不得覆盖原始快照，用户仍有主动修订和删除权。

**第二层：结构化资料与候选知识。** 保存概念、主张、方法、案例、证据、反例、问题、适用条件与 AI 的拆解结果。这里既有值得学习的内容，也有只需未来查找的参考资料；不要求全部晋级。

**第三层：个人知识。** 保存用户自己的解释、应用、边界认识、经确认的来源关系与综合笔记。AI 可以整理表达，但不得把自己生成的答案直接冒充用户已经理解的知识。

三层是内容组织，不是“真理等级”。学习状态、复习状态和检索权限应分别管理；晋级不要求复制或搬动同一内容来制造多份互相冲突的笔记。学习工作区和索引也不是额外的永久知识层。

## 3. 资料输入、AI 拆解与前置核验

### 3.1 输入与来源追踪

Web 支持快速粘贴、批量导入、补充来源、查看处理进度、编辑与归档。应用内 AI 对话的有用片段可由用户选中送入第一层，不能把所有聊天自动当作知识。

来源与知识采用多对多关系：一个视频可以产生多个知识点，一个知识点也可以引用多个来源。重复内容应尽量合并知识节点、补充来源；实质分歧不能以去重为由抹掉。

来源记录统一保存平台、作者、原始地址、日期、获取时间与可用的原文定位。知识记录通过统一的 `sources` 或等价引用机制连接来源，不重复堆叠 `source_type` 与 `derived_from`。引用关系应能区分“原始输入”“支持”“反对”“适用限制”，避免把资料出处和证据作用混为一谈。

### 3.2 拆解规则

AI 应保留核心问题、主要结论、论证、关键概念、例子、条件、限制和未知处，允许按材料类型调整结构，不要求每条笔记填写空洞的固定栏目。

应区分“原作者说了什么”“外部证据说明什么”“AI 推断或补充什么”。不能为了简短而删除决定结论的条件；不能机械拆到句句独立、失去上下文。适度的原子知识与综合主题笔记应并存。

### 3.3 核验发生在第二层加工阶段

对于可以外部检验的事实、概念定义、数据、经验性因果主张，由 AI 在拆解时主动检索网页并阅读相关内容。纯价值判断不做真伪判定；事实与价值混合的句子，应拆开核验其中的事实前提。不同学科存在不同定义时，保留语境，不强行确定唯一版本。

核验应优先追溯一手资料，检查证据是否真的支持具体主张，注意时间、样本、地区和适用范围。主动寻找有意义的反证、反例与相反解释，但不为了“平衡”给证据悬殊的说法相同权重。多个网页转述同一个消息不能被当作多份独立证据。

保存可点击来源、实际读到的相关摘录或摘要、定位和最后核验时间。**不设置知识置信度或已验证/未验证标签**，也不要求用户给事实打分；证据不足、来源冲突和适用限制直接写进正文。来源身份不是自动正确性的证明。

### 3.4 核验失败与变化处理

搜索和网页读取必须是真实工具调用，而不是要求模型凭记忆“假装联网”。大模型 API、搜索能力和网页获取能力要分别确认，不能假设任意模型接口自带浏览能力。

检索失败、无法读取原文、预算耗尽或证据不足时，保留原始资料，给出原因，并进入待补充研究或可重试的处理任务。已读到的可靠部分可以保留，但未经支持的事实不得被包装成定论、默认送入学习题目。自动化负责继续处理，而不是把常规核查工作转嫁到用户的学习阶段。

这里允许“任务运行中、失败、等待重试”等工程状态，它们不等于被取消的知识验证标签。核验是有证据的查证过程，不是对所有事实作绝对真伪保证。

对容易变化的事实保存核验时间；使用时发现陈旧风险或新反证，应触发重新核验、修订或停用。旧版本可追溯，但不能继续作为默认现行结论。
## 4. 知识晋级：把保存、内化和整合分开

晋级机制同时判断三件事：**是否值得以后查找、是否值得投入学习时间、是否值得建立长期联系**。这三者不能用一个“重要性分数”代替，也不要求保存的资料都进入复习。

| 用途或阶段 | 应有的产品行为 |
|---|---|
| 原始存档 | 保存来源，不默认拆解到底或强制学习 |
| 参考资料 | 已整理、可检索，通常无需主动记忆 |
| 候选池 | 保留潜在价值，允许延迟决定 |
| 主动学习 | 进入当前主题和有限的学习队列 |
| 已整合知识 | 已形成用户自己的理解，按需要复习与应用 |
| 核心知识 | 在长期使用中表现出基础性、生成性或迁移价值，侧重跨情境应用 |
| 停用或被替代 | 保留历史与替代关系，退出默认教学与现行答案 |

这是行为要求，不强制实现成一个单一状态字段；“原始存档”也不要求与后续笔记拥有相同数据类型。

**晋级理由。** 综合当前项目与目标、前置知识价值、反复出现、实际使用、跨领域迁移、改变已有理解及忘记的代价。给出可读的理由，而不是伪精确的 0—100 评分。重复出现要排除转载与系统自行制造的重复。

**动态调整。** 候选知识可在后续使用中晋级；已学知识可降低复习频率、暂停、重新学习或被新结论替代。用户可覆盖 AI 建议。AI 可以自动整理候选与参考资料，但不能仅凭自己的判断宣称用户已经掌握；正式个人笔记需用户确认。

**防止自我强化。** 被系统检索、展示或链接很多次，不等于真正有用。晋级不能主要靠这些由系统自己制造的曝光信号，应结合用户主动调用、实际输出、纠错和明确反馈，也保留少量探索新主题的空间。

**学习深度。** 每项知识可以以“知道存在”“知道去哪找”“能够解释”“能够迁移应用”为不同目标。具体参数可能只需可查，基础机制才值得内化。完成一次答题不等于永久掌握；较高层目标需要后续保持或应用表现的支持。

系统必须区分**知识处理/候选队列**与**今日学习队列**。前者处理资料与晋级建议，后者只安排用户当下值得投入时间的内容，避免“今天收集多少，就必须学多少”。

## 5. 主题学习与费曼式互动

### 5.1 把碎片组织成主题，而不是按入库日期排列

AI 根据当前目标、内容关系、前置概念和用户已有理解，形成可调整的主题学习包。每个学习包说明要解决的问题、学习顺序、涉及的知识、缺失前置知识和预计投入；用户可以合并、拆分、暂缓或自行指定主题。

主题可以跨越文件夹和标签。同一天输入不同领域的材料，不应因此被强行排成一节课；反过来，不同日期积累的相关内容应能聚合。不要给所有孤立材料强造关系，零散内容可以继续待在参考库。

缺失前置知识时，AI 可建议补充材料，但新增事实也必须经过同一来源与核验流程。不能把 AI 生成的“课程背景”自动当成已学知识。

主题地图主要服务于阅读和学习导航，可采用大纲、关系列表或简明图形，不必实现复杂图谱。用户编辑确认的综合地图属于长期资产；纯自动生成的摘要可以重建。

### 5.2 学习回合

普通知识采用轻量回忆与解释；高价值知识提供更深入的追问。交互应按用户回答逐步推进，而不是一次倾倒大量问题。

默认流程是：先学习必要材料，再隐藏答案主动回忆，用自己的语言解释，随后接受机制、条件、例子、反例、概念比较及陌生场景应用的追问。允许分级提示和查看原文，但应区分“独立作答”与“得到提示后作答”。

AI 反馈要指出具体遗漏或错误、依据和改进方向。评价目标是理解是否正确，不是措辞是否像标准答案。存在争议、价值分歧或题目本身不清楚时，不得机械判错。

原始回答、AI 建议与用户最终确认的笔记必须可区分。AI 不能直接替用户写出“我的理解”并自动晋级；用户可采用建议，但保留修改过程和最终确认。

本产品把“费曼式学习”落实为解释、追问与应用，不把它当作保证学会的品牌化步骤。主动提取练习有原始实验支持，但具体效果仍与材料和任务有关，不能据此承诺固定掌握速度。[3](https://pubmed.ncbi.nlm.nih.gov/21252317/)

## 6. 错题库与长期复习循环

### 6.1 错题库记录误解，而不只是错题截图

每条错误记录至少能还原：相关知识、当时的问题、用户实际回答、错误或遗漏、修正解释与依据、后续练习以及纠正情况。相同误解可合并历史，跟踪是否反复出现，不需不断生成重复卡片。

支持概念混淆、因果跳跃、遗漏条件、错误事实和应用错误等情况；具体分类由开发模型决定。用户可以质疑、撤销或修改 AI 的判定。尚未解决的争议不能被当成已确认错误反复训练。

错题及其修正应能在 Web 和 Obsidian 中阅读。**错误答案不能作为普通正确知识进入默认 RAG 上下文**；需要调用时，必须连同纠正说明和错误身份返回。

### 6.2 每日复习清单

每日任务结合当前主题、到期复习、薄弱点、当前项目及少量跨主题迁移。新知识优先成体系理解，旧知识再分散复习；比例、间隔和算法可调整，不照搬固定天数或固定百分比。

用户设置每日时间预算、关注主题和暂停项。系统提供安排理由、预估投入、开始入口、完成反馈、跳过、延期和暂停。积压过多时应重新分流、降低新增学习量或调整安排，不能无限追加“欠债”，也不能伪造完成记录。

复习表现应基于实际回答、提示使用、错误再现和应用情况，不依赖“我觉得掌握了 80%”。核心知识主要训练跨场景调用；参考资料通常不进入记忆任务。

### 6.3 真正的自动化，而不是浏览器倒计时

每日清单由持久化的后台调度生成，生成时间和时区可配置，默认采用用户确认的本地时区。关闭页面但服务仍运行时，任务仍可执行；运行主机关闭或休眠时，不承诺执行，恢复后应补算今日需要的任务。

调度要防止重复执行造成重复任务、重复笔记或重复计费；失败可查看、重试和取消。任务计划、作答历史与调度状态须在重启后保留。

没有模型或网络时，仍可读取已有资料、编辑笔记、查看已生成任务和保留回答；需要 AI 的批改、研究与新题生成应明确显示不可用或等待处理，不伪造结果。

## 7. 自动关联与持续发现

### 7.1 新入库时做局部关联

每新增或实质修改一条知识，利用关键词、语义检索和已有关系召回有限候选，再判断哪些关系值得保留。允许先从简单索引实现，但不得默认把整个知识库文本重新发送给模型逐篇比较。

关键词与语义检索各有用途：前者便于精确术语、日期和名称匹配，后者便于不同措辞下的概念匹配；混合检索可组合两者。[4](https://learn.microsoft.com/en-us/azure/search/hybrid-search-overview) 检索范围由授权控制，标签只辅助排序与导航，不能成为默认的跨领域隔离墙。

### 7.2 为高价值知识寻找非显然联系

不能只搜索“类似内容”。应从共同机制、相反结论、边界条件、已有难题、当前项目和可能应用等角度扩展查询，寻找迁移机会。

关联结果须说明“联系在哪里、可能有什么用、依据是什么、类比在哪里失效”。词语相近不等于机制相同，相关性不能自动写成因果关系。探索预算和候选数量由实际效果与成本决定，不承诺穷尽所有联系。

### 7.3 周期性检查全局结构

系统可按计划或手动检查主题摘要、知识群组、孤立节点、跨主题桥梁、矛盾和长期未被调用的材料，生成可阅读的发现报告。应重点处理新增和变化内容，并保留一定跨主题探索，避免不断强化原有主题。

这项能力必须存在，但不强制使用完整 GraphRAG；轻量主题归纳、索引和有限的模型分析也可满足要求。

### 7.4 控制关系质量

明确区分“稳定关系”“候选联想”和“仅语义相似”。稳定关系应有明确含义，例如前置知识、支持、反对、例子、反例、机制类比、应用、修正或替代，而不只是“有关”。

来源引用可自动建立；模型推断的高影响关系和跨域类比默认作为建议，用户可接受、修改或拒绝。记录依据与来源，允许撤销和随知识更新重新评估，避免图谱变成无意义的密集连线。
## 8. 检索、知识库问答与内容输出

RAG（Retrieval-Augmented Generation，检索增强生成）在这里指“找出相关材料，把它们作为上下文交给模型回答”的流程，不是把第三层知识交给模型再加工一遍。

**基础检索。** 提供中文关键词、精确术语、语义搜索与组合检索；支持来源、主题、时间和知识阶段等筛选。可按需要进行候选融合、重排序和关系扩展，具体算法不限定。即使 AI 生成服务不可用，基础查找仍应可用。

**分层取材。** 默认优先用户已整合的知识，但允许补充第二层参考资料和第一层原始来源。优先级不是“第三层永远正确”：陈旧结论、有新反证的观点、历史版本和错题原答案必须区别处理。用户应能控制检索范围，看到实际用了哪些资料。

**有依据的回答。** 答案中的关键主张能追溯到知识笔记及其底层来源，必要时可在同一界面打开已保存的证据片段。区分用户已有观点、外部材料和本次 AI 推断。找不到、证据冲突或内容过期时如实说明，不凭空补出“知识库里说过”。

**输出工作区。** 用户提出写作、表达或项目目标后，系统能组织相关观点、证据、案例、反方意见、限制和未解决问题，形成素材清单、提纲或草稿。用户可编辑、标记实际采用的知识，并把使用反馈送回晋级与关联机制。

新草稿及问答不会自动成为第三层知识，防止模型反复引用自己生成的内容造成虚假的证据循环。值得沉淀的部分可由用户重新送入加工或个人理解确认流程。

## 9. 大模型 API 与 MCP 接入

### 9.1 可替换的 AI 能力

通过后端连接大模型 API。Web 可配置服务地址、模型、密钥、任务用途和预算，测试连接并查看错误。文本生成、向量嵌入、搜索与网页读取是可独立替换的能力；可以由一个供应商提供，也可以组合使用。

密钥在后端安全保存，首次录入后不向页面反显明文，不写进 Vault、导出文件或普通日志。不同模型能否支持结构化输出、工具调用等能力，应按实际接口验证，不作通用假设。

应支持长任务进度、超时、取消、有限重试、并发限制与缓存。显示调用量、耗时与可获得的费用信息；价格未知时明确未知。预算耗尽时暂停相应 AI 任务，不丢失输入。相同事实或来源可复用仍适用的核验结果，发生变化时再更新。

### 9.2 真实的 MCP 服务

MCP（Model Context Protocol，模型上下文协议）用于让支持它的 AI 应用调用外部工具与资料；它不替代模型 API，也不规定应用如何使用检索结果。[5](https://modelcontextprotocol.io/docs/learn/architecture)

本应用必须交付一个可用的 MCP 服务，与 Web 共用同一知识服务、权限和来源追踪机制。最少覆盖知识搜索、读取笔记、读取来源和查询相关知识等能力；具体工具名称由开发模型决定。

默认只读。提供可选的写入提案能力时，只能进入待确认草稿或修改建议，由用户在 Web 查看差异后确认，不能直接覆盖正式个人笔记。Web 内部无需为每次操作绕行 MCP。

按实施时的官方规范及选定客户端兼容性选择传输与 SDK，记录实测版本。至少完成一次真实兼容客户端的检索与读取测试。不能把普通 HTTP 接口改名为 MCP，也不能仅声明“将来可接入”。

本地与远程连接要分清：外部云端客户端是否能访问本地服务取决于部署与连接方式。首轮可完成本地 MCP 接入；公网开放不是必要条件，启用时必须补齐认证、授权和网络安全配置。[6](https://modelcontextprotocol.io/docs/tutorials/security/security_best_practices)

### 9.3 支持用户从项目中学习技术

在 Web 中提供简明的“系统如何工作”说明与诊断视图。用户应能观察一次文本如何被拆成检索片段、关键词与语义搜索返回什么、哪些材料进入回答、一次 MCP 调用取得了什么结果。

术语首次出现附中文解释，提供与当前项目相连的短例子。展示可核对的输入、来源、工具调用和结果，不要求展示模型隐藏推理。技术学习说明不能取代功能的真实实现。

## 10. 数据、文件与安全边界

### 10.1 三类数据必须分开

| 数据类别 | 存放与恢复要求 |
|---|---|
| 长期知识资产 | 原始文本、结构化材料、个人笔记、错题修正、确认的主题与关系，以可阅读的 Markdown 及必要附件兼容 Vault |
| 运行与学习记录 | 作答历史、复习调度、任务进度、偏好、变更记录等可以存在应用数据库，但须持久化、备份并以开放格式导出恢复 |
| 衍生索引 | 关键词索引、向量及纯自动摘要等应能重建，重建不能损失学习进度、人工修订或确认的关系 |

知识文件以 Vault 中的版本为内容权威来源；运行记录由应用持久化存储负责。若在文件与数据库间镜像属性，开发模型必须定义同步与冲突规则，不允许两边悄悄互相覆盖。

每个知识与来源需要稳定身份，不因改名或移动失去关联。具体目录和字段由开发模型设计，尽量少、可读、避免重复；不要重新加入被取消的知识置信度或验证标签。

### 10.2 Obsidian 双向兼容与可恢复性

Web 写入后 Obsidian 可正常阅读；Obsidian 外部修改后 Web 能检测并更新。保留兼容的内部链接、附件引用及不认识的原有属性，不擅自重排用户整个 Vault 或覆盖 `.obsidian` 配置。

写入应具备版本或内容变更检查、失败保护和冲突处理，尤其防止模型使用旧副本覆盖用户刚改的笔记。批量修改、合并、删除和正式知识更新应可预览与撤销；默认不允许 AI 无审批进行破坏性操作。

支持完整备份与恢复演练。用户删除内容时，应同步处理索引和缓存，说明历史版本与备份中的保留行为，避免删除后仍被正常检索或自动重建回来。

### 10.3 外部材料不拥有执行权限

网页、导入文件、模型输出和检索结果都只能作为数据，不能因为其中写着“忽略规则、上传密钥、删除笔记”就获得工具权限。提示注入可能来自被检索的网页和文档，权限约束、输入输出处理及高风险操作确认须在程序层落实，不能只靠提示词。[7](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)

文件访问限制在授权目录，防止路径越界；网页获取应防止访问未授权内部地址；渲染 Markdown/HTML 时处理脚本与危险链接。知识读取、写入与删除权限分开，本地服务也要防止未经授权的网页调用。

联网核验的查询可能泄露私人信息。允许将资料或范围设为仅本地；外发前最小化所需内容并去除无关隐私。未经授权不能为了核验或跨领域探索把整段私人对话或整库发给外部服务。受隐私限制无法核验时，明确保留这一限制。

## 11. Web 界面的功能覆盖

下面是工作区职责，不是必须照搬的菜单数量或页面布局。

| 工作区 | 必须能完成的操作 |
|---|---|
| 今日工作台 | 查看主题学习、到期复习、错题与待确认事项，调整今日负担 |
| 收集与加工 | 输入与批量导入、补来源、看原文、看核验材料、重试、合并、分流和晋级 |
| 学习与复习 | 隐藏答案回忆、逐步追问、查看反馈、管理错题、确认个人笔记 |
| 知识浏览与发现 | 搜索、编辑、主题导航、关系说明、接受或拒绝联想、查看发现报告 |
| 问答与输出 | 带来源问答、查看引用片段、组织素材、生成并编辑提纲或草稿 |
| 系统与技术学习 | 模型和搜索配置、调度、费用、任务日志、Vault 管理、备份恢复、MCP 与检索诊断 |

任务状态、失败原因和用户下一步操作必须可见。已经保存的来源摘录、笔记和学习历史可在应用内查看；打开外部原始网站是补充动作，不应成为完成日常流程的必要条件。

## 12. 施工顺序与阶段交付

采用“先跑通一条真实闭环，再增强质量与规模”的顺序。安全写入、来源追踪和持久化从第一阶段开始，不留到最后补。下表是依赖关系建议，可以调整，但最终范围不能缩减。

| 阶段 | 主要成果 | 阶段完成的依据 |
|---|---|---|
| A：设计与基础 | 简要架构、数据责任划分、Web 骨架、Vault 安全读写、API 配置、原始输入与基础搜索 | 真实文本可从 Web 保存，外部修改能回读，真实 API 调用成功 |
| B：加工与晋级 | 拆解、联网核验、证据和反例、去重、参考/候选/学习分流 | 一份混合材料完成可追溯处理，失败与不确定情况有正确出口 |
| C：学习闭环 | 主题学习包、主动回忆、追问、个人笔记、错题、间隔复习与每日调度 | 学习与纠错过程持久化，关闭页面和重启后任务状态正确 |
| D：检索与发现 | 语义与混合检索、分层 RAG、局部关联、周期发现、内容输出 | 精确查找和换词查找均可用，关联有依据，输出有来源 |
| E：外部接入与完整交付 | 真实 MCP、写入提案、技术学习视图、集成测试、安装说明与恢复演练 | 核心验收全部完成，剩余限制逐项披露 |

开发过程中维护一份简短的“需求—实现位置—测试证据”对照表，防止多模型或分阶段施工时遗漏功能。允许用模拟接口做单元测试，但最终外部能力验收须使用真实连接。
## 13. 最终验收场景

以下是交付底线，不规定测试框架。开发模型应补充必要的边界测试，并记录实际结果。

| 场景 | 应观察到的结果 |
|---|---|
| 单窗口完整流程 | 从粘贴材料到核验、学习、复习、检索和输出，均能在 Web 内完成，内容真实落盘 |
| 事实与观点混合输入 | 事实有真实网页依据或明确的不确定说明，价值判断不被强行判真伪，原文和反证可追溯 |
| 搜索、模型或预算失败 | 资料不丢失，任务可恢复，不伪造已核验、已学会或已完成状态 |
| 重复与分歧 | 同一知识能汇集多个来源，不反复生成学习任务；相反意见不会被错误去重 |
| 晋级与学习负担 | 同批资料可分别进入参考、候选和学习；任务受时间预算约束，AI 解释晋级理由，用户能覆盖 |
| 跨领域碎片组织 | 不按当天导入顺序机械教学，可跨日期聚合主题、指出前置缺口，用户能调整学习包 |
| 费曼追问与错题 | 用户原回答被保留，追问暴露具体误解，错题关联回知识，判错可质疑，后续能针对性复习 |
| 每日任务与重启 | 页面关闭后后台仍按条件运行；主机恢复后补算；重复触发不重复记账、建任务或改进度 |
| 局部与全局关联 | 新知识有有限候选关联，周期报告能提出跨主题联系或矛盾；说明理由与边界，并能拒绝建议 |
| 检索与有据输出 | 精确术语和同义改写都能找到预期材料；答案和提纲能回到笔记与来源，无结果时不编造 |
| 错误与旧结论隔离 | 错题原答案、被替代结论和 AI 草稿不会被当作默认正确知识；必要引用时身份清晰 |
| 双向编辑与索引重建 | Web/Obsidian 修改均可同步，重命名不丢关联，冲突不静默覆盖；重建索引不丢作答与复习历史 |
| 备份、恢复与删除 | 恢复后知识和学习进度都在；删除后正常检索无残留，历史与备份保留策略明确 |
| 真实 MCP 与权限 | 兼容客户端实际搜索、读取成功；未经授权的读取或覆盖被拒绝，写入提案须经 Web 确认 |
| 注入与隐私 | 恶意网页或笔记不能触发越权文件操作、密钥泄露或额外外发；仅本地资料受到保护 |

另外建立一组小型、可重复的质量检查材料，覆盖中文精确查找、同义提问、跨领域关联、错误引用、事实争议和错误批改。不能只凭一次“回答看起来不错”认定质量合格。

性能与成本按实际测试环境记录资料规模、处理耗时、检索响应、AI 调用量和失败情况；不虚构未经测量的容量保证。没有真实 API 凭据或兼容客户端时，应明确相应验收尚未完成，附上可执行的验证方法，不能用模拟成功代替实测。

## 14. 开发模型应交付的材料

交付可运行的源代码、必要依赖与配置示例、简明启动和停止方式、Web 首次配置引导，以及不含个人隐私的演示数据。演示数据和演示学习记录必须清楚标识，不得冒充用户的真实知识或掌握历史。

附上简短的架构与关键选型说明、数据存放及备份恢复说明、模型和搜索服务接入说明、MCP 连接与实测说明、自动任务运行条件、测试结果和已知限制。技术文档应帮助初学者理解系统，不需要扩写成通用技术教材。

未指定的实现细节由开发模型选择合理默认值并记录。对会影响费用、数据外发、破坏性操作和远程开放的设置，应提供明确控制，不得悄悄替用户作高风险决定。

**交给开发模型的执行说明：** 以本文件为独立需求依据，先形成简要实现方案和需求覆盖表，再按可运行闭环分阶段实施。可以调整名称、模块划分和技术方案，但保持产品行为与验收条件。不要把任务再次退回泛泛的知识管理讨论，也不要只交付页面原型、聊天壳或接入占位符；真实实现、测试证据与未完成事项必须明确区分。
