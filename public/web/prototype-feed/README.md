# 趣味学习信息流原型（待选择，禁止自动发布）

回答的问题：抖音式连续浏览，怎样与知序的到期复习、费曼追问、答后反馈结合，而不把“刷过”当作“学会”？

## 打开

在本分支根目录运行 `pnpm prototype:feed`，访问：

- A 沉浸刷学：<http://127.0.0.1:4361/web/prototype-feed/?variant=A>
- B 图文发现：<http://127.0.0.1:4361/web/prototype-feed/?variant=B>
- C 边刷边练：<http://127.0.0.1:4361/web/prototype-feed/?variant=C>

仅需 Node.js 24，不需要安装新增依赖。端口可通过 `PROTOTYPE_PORT` 指定。独立预览器只绑定回环地址、只提供三份列入允许清单的静态文件；`NODE_ENV=production` 时拒绝启动。它不启动知序服务、调度器或数据库。

底部左右箭头或键盘左右键切换方案；输入时保留方向键编辑。上下滑动、滚轮、上下键切换知识。首条向下拖动超过阈值后松开，或点击“换一批”，刷新内容；推荐流最后一条继续上滑会换批。刷新轮换六条演示内容，不表示获取了新知识。

## 三个方向

| 方案 | 布局与主操作 | 取舍 |
| --- | --- | --- |
| A 沉浸刷学 | 全屏单条图文，右侧行动栏；需要练习时打开浮层 | 最接近抖音；浏览轻松，练习需要主动打开。 |
| B 图文发现 | 先浏览图文网格，再进入图文详情和连续浏览 | 适合自主挑选；开始学习多一次点击。 |
| C 边刷边练 | 左侧连续知识流，右侧常驻回忆、反馈和追问 | 桌面学习连续；小屏收敛为单流与底部练习面板。 |

用户已指定抖音界面、刷新方式和图文截图。依 SSoT 第 2 步跳过方向抽样，按固定参考明确设计三个结构方向；没有先选布局再伪造种子。此处不采样学习规则。新信息流目前没有既存页面，选择独立原型路由，但保留知序侧栏、叶子图标、温润配色和已有缓动。

## 范围

- 六份自编合成学习笔记，三个演示到期项。原始附图不进入仓库，借鉴其纯色背景、大字疑问、划线和图文层级。
- 复习与新知交替轮换；没有训练或模拟真实兴趣算法。兴趣与收藏只记录在当前页面内存。
- 先回答，再展示预设对照要点和追问；清楚标注“不是 AI 对你回答的评判”。无模型调用、费用或真实能力验收。
- 保留原回答、后续草稿、看原文/提示记录。滑过与收藏不记完成；提交后仍需点“结束本轮”。不改变掌握等级或真实复习日期。
- 切换方案、知识和分类保留内存状态；浏览器重新加载即清空。底部“状态”显示完整相关状态，方案切换和主要操作也写入控制台。
- 不接触真实资料、权限设置、凭据、正式 4318 或桌面入口。

## 本次验证（2026-10-25）

实际在 Codex 浏览器检查 A/B/C 桌面布局、B 图文详情、C 常驻反馈，以及 390 × 844 窄屏；检查上下拖动、首条下拉刷新、收藏筛选、回答→追问→结束本轮、待复习队列完成状态、滑走再返回的草稿。移动端按钮增加暗色底以保证浅色封面上的可辨认性。

仅运行原型语法检查和项目既有仓库检查，不新增测试套件，不运行全量产品回归。原型客户端三文件合计约 50 KB，无外部请求、运行时依赖、空闲轮询或视频解码；一次只挂载一张阅读卡，发现页只挂载六张。

真实手机触摸、系统键盘和橡皮筋回弹尚未验收。Codex 内置浏览器不支持 Input.dispatchTouchEvent；窄屏手势证据是浏览器拖动输入，不当作实体手机测试。减少动效样式和键盘直接切换在代码中保留。

参考：2026-10-25 实际打开 [抖音推荐页](https://www.douyin.com/)，观察到滚轮、键盘上下键及右侧上下按钮的引导。移动下拉交互为本次原型方案，不声称已逐项实测抖音移动客户端。没有复制抖音媒体、字体或用户内容。

## 踩坑记录

- 待复习队列在结束本轮时不能立即移除当前项，否则反馈面板会跳到下一条知识。当前采用进入分类时的队列快照；换批或重选分类时再更新待复习集合。
- 浅色封面上的白色侧栏图标可读性不足，小屏应提供稳定的深色背景。
- 参考浏览器连接不可用时记录实际失败；不能把窄屏鼠标拖动描述为真实触摸验证。

结论：三种结构均可把浏览与练习接通，候选交互已可体验；最终方向仍待用户选择。
