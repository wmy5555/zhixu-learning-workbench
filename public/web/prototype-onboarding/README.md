问题：新版知序里，哪一种分步引导结构既顺手、不遮挡操作，又能让未来 AI 助手复用准确的步骤？

这是一次性候选，未决定采用方案。仅保存在 `feat/onboarding-prototype-20261021`，不合入 main，不纳入正式部署；正式实现需另行设计适配和验证。主工作区及正式 4318 均未修改。

## 运行与体验

在本分支根目录运行 `pnpm prototype:onboarding`，或直接运行：

```sh
node public/web/prototype-onboarding/serve.mjs
```

默认访问 `http://127.0.0.1:4341/?variant=A`。可用 `PROTOTYPE_PORT` 指定其他空闲端口，服务只监听 127.0.0.1。生产环境模式拒绝启动。

- A 轻随行：浮动向导贴近操作，为其预留空间；推荐先试此版。
- B 并肩学：侧栏展示阶段与当前任务，短窗口采用紧凑路线。
- C 对话伴：底部陪伴条结合按需问答，从具体问题提出路线。

底部切换栏及左右方向键切换方案；输入框内方向键不切换。方案切换保留本次进度。Escape 关闭最上层弹窗；没有弹窗时收起引导。暂停与重新定位保留输入。刷新会清空全部原型状态。

材料只用原创虚构示例。连接、拆解、反馈、复习日期、草稿都是模拟行为，没有 API、数据库、localStorage 或正式资料读取。真实模型、权限、计费及学习结果未验收。扩展专题仅展示入口，未搬迁旧版 89 个扩展步骤。三个场景用于判断交互动线，不代表旧版素材库全部迁移。

## AI 助手接入契约

`catalog.mjs` 是唯一的步骤目录，包含 `id / version / chapter / view / target / fallbackTargets / requires / evidence / expected`。执行器负责定位、检查前置条件和完成证据，AI 不控制 DOM 选择器或直接修改事实。

浏览器提供 `window.zhixuGuide`：

| 接口 | 作用 |
| --- | --- |
| `getCatalog()` | 返回步骤目录副本。 |
| `getContext()` | 返回练习范围、当前步骤、事实、缺失条件、目标可见状态、事件；不包含资料正文、回答或凭据。 |
| `proposeGoal(goalId)` | 为已注册目标生成路线，递归补齐缺失依赖并跳过已完成动作。 |
| `presentPlan({schemaVersion:1, goal})` | 按当前状态重新生成受支持路线，展示给用户；不采纳外部步骤列表或任意选择器。必须由用户点击开始。 |
| `pause()` / `resume()` | 暂停或恢复当前路线，不改变完成证据。 |
| `zhixu:guide-event` | 在 window 上广播步骤打开、原型操作证据、路线确认等事件；来源明确标注模拟。 |

当前自然语言入口是本机关键词规则演示。未知意图请求澄清，多意图展示选择；不声称具备真实 AI 语义理解。未来模型应只提出已注册目标，或在扩展契约后提出受校验的步骤计划。真正接入前需要将 facts 替换为绑定练习库 ID、资料 ID/版本与操作回执的证据适配器，并处理迟到响应、权限撤销、路由变化及保存冲突。模型不能写入“已完成”、自动开启外发、执行付费调用或代用户确认理解/采用。

目标暂时丢失时停止推进并给出重新定位；缺前置时提供补齐路线与返回位置；模拟连接失败后保留配置并允许重试。更换已保存材料会清除下游完成事实。模拟请求晚到只更新证据，不自动切换步骤。
